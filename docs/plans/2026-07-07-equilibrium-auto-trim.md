# 平衡点オンライン自己推定・自己調整 (equilibrium auto-trim) 設計計画

日付: 2026-07-07 / 状態: 提案 (ゲート1未実施)
背景ブランチ: dev/udp-telemetry (実機較正・バースト耐性化済み)

## 0. 動機 (実機観測)

- 平衡点近傍で「ピタッと静止 → 微小外乱 → 一気に振動」を実機で確認。静止摩擦コーン内で
  機構的に静止できる事実は線形不安定(過剰ゲイン)説を否定し、スティクション由来の
  リレー型リミットサイクル(実測3.2Hz・振幅一定・電流同位相・非飽和)と整合する
- 平衡点の較正残差・重心変動(バッテリー位置等)に対し、固定 pitch_eq では脆弱

## 1. サーベイ結論 (要点)

文献系 (一次情報、詳細は調査ログ参照):
- **平均電流ゼロ化による平衡点推定**: 定常で復元トルクを受け持つ電流バイアス
  ī から Δθ̂ ∝ ī を推定。**スティクションで静止中も電流バイアスは残るため、
  速度ベース学習が沈黙する条件で唯一学習信号が生き残る** (本システム最重要知見)
- ESO/ADRC: TMS320実機実績 (ω_o=25, ζ=0.707, 143Hz)。200Hz MCUで実装容易。
  「ESO残差を教師信号に低速学習器で平衡点を更新」の二段構成 (arXiv:1810.03076)
- リミットサイクル除去には平均化窓をLC周期(0.31s)の数倍(1〜数秒)に取る
- NVS永続化は「RAM学習(毎周期) → 収束判定+レート制限付きで低頻度書込」の二段が定石

実装系 (OSS 15件コード実査):
- **「電流制御モード × 走行中自動trim × 自動永続化」を全て備えた前例は無い** (空白領域)
- 自動trimの実体は全て積分器。優良3パターン:
  - YABR: PID出力の符号を±0.0015°/4msで基準角へ符号積分 (最小実装、クランプ無しが弱点)
  - milana_robot: 理論/実測加速度残差を積分、クランプ±0.2rad・平滑0.998・回頭中ゲート・
    転倒リセット完備 (最も本番品質)
  - SimpleFOC balancer: 速度誤差→PI(I=0.03)→LPF(0.07s)→基準角 (トルク指令モードで唯一)
- 転倒/停止時のtrimリセットと積分クランプが実用実装の分水嶺

## 2. 設計: 3層 + 1イネーブラ

時定数のデカード分離を原則とする (干渉防止):
ピッチループ(数Hz) ≫ 速度ループ(~0.3Hz) ≫ 平衡点trim(~0.03Hz) ≫ NVS(分オーダー)

### L1: 既存速度ループ (現状維持)
kv/kvi → θ_ref (±3°) は運動中の高速な平衡点追従として既に機能。変更しない。

### L2: 平均電流ベース平衡点推定器 EqTrimEstimator (新規, core/)
- 入力: i_cmd_l + i_cmd_r の平均 (送信実績値 last_cmd。読取無効周期は凍結)
- ī = LPF(i_sum/2), 時定数 τ_i = 2.0s (LC周期0.31sの約6倍)
- 更新則: eq_trim += k_trim · ī · dt
  - k_trim 初期値: 0.5 deg/s per A 相当 (=0.0087 rad/(A·s))。符号は実機の符号試験で確定
    (正電流=前進駆動が定常的に必要 ⇒ 想定平衡より前傾 ⇒ pitch_eq を前へ)
- ゲート (更新する条件):
  - FSM == Balancing かつ |v| < 0.05 m/s (指令走行中は学習しない)
  - fb.valid の周期のみ (欠落周期は凍結、リセットしない — uprightHold と同じ教訓)
- クランプ: |eq_trim| ≤ 3° (較正済み kPitchEqDefaultRad を中心)
- レート制限: |d(eq_trim)/dt| ≤ 0.1°/s
- リセット: Fallen/Fault/Disarmed 突入時に **保持** (ゼロクリアしない。転倒は平衡点の
  誤りではなく外乱由来のため。ただし LPF状態はリセット)。milana/YABR と異なる判断 —
  根拠: eq_trim はクランプ済みで、保持により再起立後すぐ恩恵を受ける
- 実効平衡点: pitch_eq_eff = params.pitch_eq + eq_trim (θ 計算の単一変換点で加算)

### L3: trim transfer + NVS 永続化 (新規)
- θ_ref (kvi積分) の定常値も平衡点誤差の推定を含むため、|θ_ref|のLPF が閾値(0.3°)を
  一定時間(10s)超えて安定なら、その値を eq_trim へ 0.01/s の速度で移し替え (θ_ref 側は
  自然に再センタリングされる)
- 永続化: Balancing→(Idle|Fallen) 遷移時、|eq_trim| > 0.1° かつ 前回保存から60s 以上なら
  params.pitch_eq += eq_trim; eq_trim = 0 とし、既存の保存ゲート機構(§9.1)経由で
  SaveKind::Params を自動要求。書込は従来どおり UI タスクが safe-off 検証下で実行
  (NVS摩耗: 最悪 1回/60s、実運用ではセッション毎に1-2回)

### E: スティクション補償 FF (イネーブラ, 新規)
- PID+速度ループ合成後: |i| > 5mA なら i += sign(i)·kStictionFFA (初期 0.035A)
- 目的: リレー非線形の位相遅れ低減 → リミットサイクル振幅縮小 → ī のS/N向上
  (L2 の学習信号品質を上げる前処理として位置づけ)
- 実測でLC振幅が縮小しない場合はディザ(±0.03A, 40Hz)へ切替を検討
- ゲイン: Kp は 1.5 へ戻す (実証済み動作点で単変量評価)

## 3. 安全性検討

- 全追加は core/ 純ロジック (Arduino非依存、native テスト対象)
- eq_trim クランプ±3° + レート制限0.1°/s により、推定器暴走時も θ の解釈が
  最大3°ずれるのみ (転倒閾値35°、起立窓±5°に対し十分小)
- FSM・フォルト経路・Bus Watchdog 規律は不変
- 電流妥当性監視 (i_cmd vs i_pres) は FF 適用後の送信値で比較するため影響なし

## 4. 実装順序と検証

1. E (FF) + Kp=1.5 復帰 → ベンチ: LC振幅 sd 3.2°→目標<1.5°、テレメトリで確認
2. L2 (RAM のみ) + テレメトリへ eq_trim/ī フィールド追加 → 意図的に重り追加し
   eq_trim が収束すること・時定数(~30s)を確認
3. L3 (transfer + 自動保存) → 再起動を跨いで収束値が引き継がれること
4. (発展) ESO 化: L2 を明示的 ESO に置換し残差ゲーティング (文献 ω_o=25 帯)

各段で native テスト追加 (EqTrimEstimator 単体: ゲート/クランプ/凍結/移し替え)。
